# Project: Job Function Configurator

## Context
- This is an integration for the OS2mo application (https://github.com/OS2mo) that runs as a separate docker-compose service.
- This integration has the sole responsibility of maintaining the `extension_3` field of engagements in OS2mo.
- This integration is event-driven: it listens for engagement events from OS2mo and writes `extension_3` in response.

## Running Tests
- Integration tests are in `tests/integration/`, and are marked with `@pytest.mark.integration_test`
- Integration tests require the OS2mo stack to be running, you can clone it from: https://github.com/OS2mo/os2mo
- Tests are run in the integration's own container, which is on the same docker network as OS2mo
  - `docker compose run --rm configurator pytest` runs all tests
  - `docker compose run --rm configurator pytest -m 'not integration_test'` runs only the unit tests
  - `docker compose run --rm configurator pytest tests/integration` runs only the integration tests

## Conventions
- The FastRAMQPI settings are nested under `fastramqpi` in `job_function_configurator/config.py`, so they are read from `FASTRAMQPI__`-prefixed environment variables. This is what FastRAMQPI's test fixtures and OS2mo's CI templates expect
- The GraphQL client in `job_function_configurator/autogenerated_graphql_client/` is generated from `queries.graphql` by `ariadne-codegen`. Edit the queries, then regenerate, never edit the generated code
- Queries prefixed with `_Testing_` exist only to set up state for the integration tests
- `schema.graphql` is the OS2mo GraphQL schema the client is generated from. Its version must match `mo_graphql_version` in `job_function_configurator/config.py`
